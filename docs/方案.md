# 飞机货运 AGV 智能运输 Web 数字孪生系统 — 技术方案 v3（单舱门 / 全宽度货位 / 舱外上货）

> 基于 Vue 3 + TypeScript + Three.js 智慧工厂数字孪生项目二次开发。聚焦"货物装到舱外待命的 AGV → 载货穿前舱门进舱 → 算法规划路径 → 舱内运输 → 障碍物自动避让 → 抵达目标列 → 推入货位 → AGV 退回舱外待命"核心流程。浏览器端可视化为主、参数可配置、预留算法接入接口，不搭建真实 ROS/Gazebo 机器人仿真平台。

## v3 相对 v2 的变更（本版现状）

| # | 变更 | 说明 |
|---|---|---|
| 1 | **建模机头（机尾不做外形）** | 新增机头锥段（沿 -X 延伸 9 m 的椭圆截面壳 + 驾驶舱舷窗 + 雷达罩线 + 机头标牌）；**机尾不建尾锥**，仅保留平直后隔框与「机尾 · TAIL」标牌，避免与机头外形混淆 |
| 2 | **只保留一个前舱门** | 删除后舱门；右舷仅一处门洞，其余整段封闭。门洞净高由 2.0 m 提高到 **2.5 m**，保证载货 AGV 直接穿门不超高 |
| 3 | **AGV 舱外待命 + 货物直接上车** | AGV 初始停在前舱门外装卸平台待命；任务下发后货物**直接出现在 AGV 上**（不再经过门外平台生成与舱内交接位滑入），由 AGV 载货穿门进舱 |
| 4 | **取消 AGV 专用通道** | 货舱地板全宽度可放货：左舷 L / 中央 C / 右舷 R **三排货位**（共 `3 × slotCount` 个），不再绘制/预留中央通道，也不再限制载货走廊 \|Z\|≤0.5 |
| 5 | **入位方式改为"推入"** | AGV 停在目标列前方 `PLACE_PUSH = 1.8 m` 处，货物沿 +X 推入货位；AGV 本体不进入货位，避免与已装货柜干涉 |
| 6 | **货位由机尾向机头填充** | 保证 AGV 从机头一侧空场进入时，沿途货位始终为空，不会压到已装货柜 |
| 7 | **AGV 运动学改为"边走边转 + 最小转弯半径"** | 巡航速度 **0.8 m/s**；角速度上限 = 速度 / 最小转弯半径 **1.2 m**，全程不允许原地掉头；目标在车尾方向时**自动倒车**（`agv:command` 的 `reverse: true` 或车端自动判定）；演示路径做**半径 1.2 m 圆角化**，避免"追直角"甩尾扫墙 |
| 8 | **舱门常开、无门扇、面板不再暴露门参数** | 只保留 AGV 旁边的这一处舱门开口（含门框）；左舷为整面封闭舱壁；删除门扇、开/关门动画与按钮，门参数为固定结构值 |
| 9 | **安全间隙校核与报警** | 每 6 帧用"AGV+货物"有向矩形（OBB）校核到四面舱壁（右舷门洞豁免）与已放货柜的净距：**< 250 mm 报警（红环 + 日志）**、**< 0 记为干涉**；宽体货（PMX/PAX）扫掠半径大于两侧排净宽，**只允许放中央排** |

> **取景与坐标系说明**：机体坐标原点 O 位于**货舱前隔板中心**；+X 指向机尾，机头锥段位于 **X<0**（即 -X 方向为机头/航向），+Y 向上，+Z 指向前方左侧（左舷）。单位米。

## 1. 坐标系与空间基准（硬约束）

飞机右手坐标系：**货舱前隔板中心为原点 `O(0,0,0)`**；`+X` 逆航向（指向机尾）；`+Y` 竖直向上（地板上表面 `Y=0`）；`+Z` 指向飞行方向左侧（左舷/port）。机头锥段位于 `X<0`（沿 -X 向前延伸 `nose.length`，默认 9 m）；机尾不做锥段，止于 `X=hold.length` 的平直后隔框。

校验右手性：`+X × +Y = +Z`（机尾方向 × 竖直向上 = 左舷），成立；与 three.js 默认 y-up 右手系**同构**，场景直接按该坐标建模，无需轴重映射。物理单位 `1 = 1 m`；ULD/门等按米建模（毫米数据先 ÷1000），换算仅经 `src/utils/coord.ts`。

方向语义备忘（供所有位姿/航向计算引用）：`yaw=0` 车头朝 +X（机尾向）；`yaw=+π/2` 车头朝 -Z（右舷向）；`yaw=-π/2` 车头朝 +Z（左舷向，即进舱方向）。

## 3. 总体架构

单向数据流，场景只消费"算法源/演示编排源"输出：

```
浏览器演示编排源(占位)  ┐
MockScheduler           │ → AlgorithmEvent(下行) ─┬→ 3D 场景 FactoryScene（逐帧插值执行指令）
                        │                          └→ cargoStore（任务/AGV/货物/门/日志镜像）
AlgorithmAdapter        │                            ↑        │
(真实 WS/API，预留)      ┘   ← ControlCommand(上行) ←─┘        ├─ 参数控制面板 → config 变更 → scene.applyConfig
   ▲                                                           └─ 任务下发/启停/重置 → transportBus.sendControl
   └ 用户操作（UI 面板）
```

- **演示模式（默认）**：`MockScheduler` 在浏览器内按 §6.6 几何规则生成同构消息流（非规划算法实现，仅"演示编排/可行性过滤"）。
- **接入模式**：`AlgorithmAdapter` 替换消息源，通过 WebSocket 收发同一契约；前端不实现任何规划/避障/调度/排列算法，仅忠实渲染算法输出并转发上行控制。
- **TransportMessageBus**：应用级单例总线，统一下行分发（场景 + store 各自订阅子集）与上行控制路由，并提供"场景探针"（AGV/货物位姿只读查询）供编排源作完成判定。

## 4. 消息契约（算法接入契约，代码与文档唯一依据）

**下行 AlgorithmEvent**（算法 → 前端）：

```ts
type AlgorithmEvent =
  | SceneCommand                                    // 三维指令（见下）
  | { type: 'task:state'; payload: TaskStateEvent } // {taskId,status:'queued'|'running'|'done'|'failed'|'cancelled',progress,message?}
  | { type: 'agv:state';   payload: AgvStateEvent } // {agvId,phase:'idle'|'toPickup'|'pickup'|'transport'|'placing'|'done'|'error',taskId?,cargoId?}
  | { type: 'cargo:state'; payload: CargoStateEvent } // {cargoId,status:'waiting'|'inTransit'|'placed',slotId?}
  | { type: 'log';         payload: { level:'info'|'warn'|'error'; message:string } };
```

**SceneCommand**（三维指令子集；姿态统一机体坐标 `Pose3={x,y,z,yaw}`，yaw 绕 +Y）：

```ts
type SceneCommand =
  | { type:'scene:reset'; payload:{config:CargoConfig} }          // 算法方自持配置时的全量重建
  | { type:'agv:command'; payload: AGVCommand }                    // moveTo|turnTo|stop|pick|place（增量指令流）
  | { type:'cargo:pickup'; payload:{agvId,cargoId} }               // 预登记取货
  | { type:'cargo:place';  payload:{agvId,cargoId,slotId} }        // 预登记放货
  | { type:'cargo:spawn';  payload:{cargoId,cargoType,pose} }      // 生成货物（如舱门平台）
  | { type:'cargo:move';   payload:{cargoId,pose} }                // 货物位姿动画（进舱滑入等）
  | { type:'path:plan';    payload: PlannedPath }                  // 荧光路径（含避障绕行点）
  | { type:'obstacle:event'; payload:{agvId,pose,radius} }         // 障碍标注（6s 自动消退）
  | { type:'slot:mark';    payload:{slotId,state:'pending'|'clear'} } // 目标槽闪烁
  | { type:'door:set';     payload:{doorId:'forward'|'aft', state:'open'|'close'} };
```

AGV 增量指令 `AGVCommand{agvId,type,pose?,speed?,ts}`；场景对 moveTo 做位置逼近 + 朝向阻尼、近目标对准、到位判定后自动执行下一条，轮组随转向角偏转示意。

**上行 ControlCommand**（前端 → 算法/演示源）：`system:init|start|pause|reset`、`config:change`、`task:dispatch{TransportTask}`、`task:cancel`、`door:override`。

**传输帧（WS 对接时）**：下行帧 `{v:1, src:'algorithm', t:<event>, ...payload}`；上行 `{v:1, dst:'algorithm', cmd:<ControlCommand>}`。详细字段与示例见 `docs/算法接入协议.md`。

## 5. 核心业务流程与状态机

| 环节 | 触发（下行事件） | 3D 表现 | 状态同步 |
|---|---|---|---|
| 任务下发 | `door:set`(open) → `cargo:spawn`(AGV 位姿) → `cargo:pickup` + `pick` | 门扇外滑开启；货物**直接出现在舱外待命的 AGV 上** | 门状态、cargo:waiting→inTransit |
| 载货穿门进舱 | `path:plan` + 多段 `agv:command moveTo` | AGV 载货穿过前舱门进入舱内，荧光路径动态绘制 | AGV:transport |
| 舱内转场 | `agv:command` 多段 moveTo（机头空场横向转场） | 位姿连续、轮组转向偏转、状态环 | AGV:transport |
| 障碍自动避让 | `obstacle:event` + 含绕行点的重规划路径 | 障碍体高亮脉冲，路径绕行重规划 | 日志记录 |
| 抵达目标列 | `agv:command moveTo(目标列前方 1.8 m)` | 目标货位 `slot:mark` 闪烁 → 精确对位 | — |
| 推入货位 | `cargo:place` 预登记 + `agv:command place` | 货物沿 +X 推入货位（AGV 不进入货位） | cargo:placed；slot:mark clear |
| 退回待命 | `agv:command` 多段 moveTo（出舱回平台） | AGV 退回舱外平台待命，等待下一件 | AGV:done→idle |
| 任务完成 | `task:state done` | 任务日志/面板更新，门关闭 | task done；AGV idle |

**两层状态机**（消除 v1 漂移）：

1. AGV 场景运行时状态（由指令/动作驱动，场景内部）：`idle | moving | aligning | pick | place | error`。
2. 任务/运输阶段（由算法源事件驱动，UI/看板展示）：`idle → toPickup → pickup → transport → placing → done → idle`（可含 error 分支）。前端只渲染，不做决策迁移。

## 6. 场景与演示几何规则

### 6.1 布局
机身剖开式：机头锥段（椭圆壳体 + 驾驶舱舷窗 + 雷达罩线 + 机头标牌）、平直机尾后隔框（带机尾标牌，不做尾锥外形）、地板/侧壁/前后隔框/顶部肋骨架；仅一个前右舷舱门（门扇外滑动画 + 门框 + 舱外装卸平台与待命标线）；三排货位格线 + 货位号文字 + 边框线；货位占用 = 实际放置的 ULD 实体（带三色类型区分与金属框线）。全部尺寸读 config，`applyConfig` 后重建受影响几何并 dispose 旧对象。

### 6.2 货物模块
参数化 AKE/PMX/PAX（主体 + 轮廓线框 + 底部托盘示意；AKE 斜角以楔形示意）；槽位 Map 记录占用/空闲；状态（待装/在途/已入位）三色指示。初始装载与目标放置共用同一"装载规格函数"（代码单一来源，保证 store 镜像与场景一致）。

### 6.3 AGV 模块
车身 + 四转向轮（随转向角偏转示意）+ 顶升平台（升降缓动）+ 状态指示灯 + 载货挂点（货物随车/随平台抬升）。仅消费外部指令。

### 6.4 路径与障碍
路径 BufferGeometry 荧光折线 + 途经点；障碍由消息标注，前端只显示包围圈 + 光柱，生命期 6s。

### 6.5 货物-货位几何适配（演示编排可行性过滤，非排布算法）
槽位列距 1.72 m：AKE 需 1 列；PMX/PAX 需**连续 2 空列**（跨列适配）。三排货位在 Z 方向互不重叠：AKE 宽 1.534、左右两排中心 |Z|=2.3，中央排 0，任意两排之间留 ≥0.76 m 净空，载货行进不会压到邻排。演示编排在选择目标货位时执行列跨度过滤；真实场景中"放哪"由算法方决定。

### 6.6 演示编排物理约束（MockScheduler 生成消息的几何依据）
- **舱外上货**：AGV 在前舱门外平台待命，任务下发后货物直接装车；载货总高约 2.3 m < 舱门净高 2.5 m，可载货穿门。
- **货位填充方向**：货位按**列号由大到小（机尾→机头）**填充，因此目标列之前（更靠机头）的货位始终为空——AGV 从机头空场进入时沿途不会压到已装货柜。
- **跨排转场只在机头空场完成**：AGV 穿门后先在 X∈(0, 6.0) 的无货位空场完成跨排横向移动，再沿目标排驶向目标列；横向平移不会穿越货位区。
- **推入式入位**：AGV 停在目标列前方 `PLACE_PUSH=1.8 m`，货物沿 +X 推入货位，AGV 本体不进入货位（避免与已装货柜干涉，也避免车体与货物穿插）。
- **避障演示**：障碍置于机头空场的转场路线上，绕行点向机头方向让开 0.8 m，仍处于无货位空场，绕行路径真实可行。
- **串行过门**：只有一扇前舱门，多件货物**逐件通过舱门**（多台 AGV 轮转分配，但不同时进舱），避免门洞互相穿插。

### 6.7 演示流程（MockScheduler 编排一个货物的完整序列）
下发任务 → 开前舱门 → 货物直接出现在舱外待命的 AGV 上(pick 挂载) → AGV 载货穿门进舱 → 机头空场跨排转场（可插入障碍事件与绕行段）→ 驶至目标列前方 → 推入货位 place → 目标货位标记清除 → AGV 退回舱外待命位 → 全部完成后关门。单货物模式 = 单任务 1 件；多货物模式 = 单任务含多件，逐件串行通过同一舱门，在多台 AGV 之间轮转。

## 10. 算法接入方式（外部算法方速览）

1. 前端不实现规划/避障/调度/排列/RL——只消费 §4 `AlgorithmEvent` 并转发 `ControlCommand`。
2. 接入：`AlgorithmAdapter` 面向 WS 连接（帧格式见 `docs/算法接入协议.md`）；前端 UI 提供模式切换与连接配置。
3. 前端需要的"位置反馈"通过场景探针/自身消息流获得；若算法方需要当前占用，可消费上行 `cargo:state`/`task:state` 或由本方维护。
4. MockScheduler 仅演示占位，不参与真实业务判定；切换接入模式后全部决策由算法方下发。
