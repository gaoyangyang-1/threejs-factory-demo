# 飞机货运 AGV 智能运输 Web 数字孪生系统 — 技术方案 v2（评审修订版）

> 基于 Vue 3 + TypeScript + Three.js 智慧工厂数字孪生项目二次开发。聚焦"货物进入飞机货舱 → AGV 自动取货 → 算法规划路径 → 货舱内自主运输 → 障碍物自动避让 → 抵达目标位置 → 货物自动排列放置 → AGV 完成任务"核心流程。浏览器端可视化为主、参数可配置、预留算法接入接口，不搭建真实 ROS/Gazebo 机器人仿真平台。

## 1. 坐标系与空间基准（硬约束）

飞机右手坐标系（用户给定）：**机头为原点 `O(0,0,0)`**；`+X` 逆航向（指向机尾）；`+Y` 竖直向上（地板上表面 `Y=0`）；`+Z` 指向飞行方向左侧（左舷/port）。

校验右手性：`+X × +Y = +Z`（机尾方向 × 竖直向上 = 左舷），成立；与 three.js 默认 y-up 右手系**同构**，场景直接按该坐标建模，无需轴重映射。物理单位 `1 = 1 m`；ULD/门等按米建模（毫米数据先 ÷1000），换算仅经 `src/utils/coord.ts`。

方向语义备忘（供所有位姿/航向计算引用）：`yaw=0` 车头朝 +X（机尾向）；`yaw=+π/2` 车头朝 -Z（右舷向）；`yaw=-π/2` 车头朝 +Z（左舷向）。

## 3. 总体架构

单向数据流，场景只消费"算法源/演示编排源"输出：

```
浏览器演示编排源(占位)  ┐
MockScheduler           │ → AlgorithmEvent(下行) ─┬→ 3D 场景 FactoryScene（逐帧插值执行指令）
                        │                          └→ cargoStore（任务/AGV/货物/门/日志镜像）
AlgorithmAdapter        │                            ↑        │
(真实 WS/API，预留)      ┘   ← ControlCommand(上行) ←─┘        ├─ 参数控制面板 → config 变更 → scene.applyConfig
   ▲                                                           └─ 任务下发/启停/重置 → transportBus.sendControl
   └ 用户操作（UI 面板）
```

- **演示模式（默认）**：`MockScheduler` 在浏览器内按 §6.6 几何规则生成同构消息流（非规划算法实现，仅"演示编排/可行性过滤"）。
- **接入模式**：`AlgorithmAdapter` 替换消息源，通过 WebSocket 收发同一契约；前端不实现任何规划/避障/调度/排列算法，仅忠实渲染算法输出并转发上行控制。
- **TransportMessageBus**：应用级单例总线，统一下行分发（场景 + store 各自订阅子集）与上行控制路由，并提供"场景探针"（AGV/货物位姿只读查询）供编排源作完成判定。

## 4. 消息契约（算法接入契约，代码与文档唯一依据）

**下行 AlgorithmEvent**（算法 → 前端）：

```ts
type AlgorithmEvent =
  | SceneCommand                                    // 三维指令（见下）
  | { type: 'task:state'; payload: TaskStateEvent } // {taskId,status:'queued'|'running'|'done'|'failed'|'cancelled',progress,message?}
  | { type: 'agv:state';   payload: AgvStateEvent } // {agvId,phase:'idle'|'toPickup'|'pickup'|'transport'|'placing'|'done'|'error',taskId?,cargoId?}
  | { type: 'cargo:state'; payload: CargoStateEvent } // {cargoId,status:'waiting'|'inTransit'|'placed',slotId?}
  | { type: 'log';         payload: { level:'info'|'warn'|'error'; message:string } };
```

**SceneCommand**（三维指令子集；姿态统一机体坐标 `Pose3={x,y,z,yaw}`，yaw 绕 +Y）：

```ts
type SceneCommand =
  | { type:'scene:reset'; payload:{config:CargoConfig} }          // 算法方自持配置时的全量重建
  | { type:'agv:command'; payload: AGVCommand }                    // moveTo|turnTo|stop|pick|place（增量指令流）
  | { type:'cargo:pickup'; payload:{agvId,cargoId} }               // 预登记取货
  | { type:'cargo:place';  payload:{agvId,cargoId,slotId} }        // 预登记放货
  | { type:'cargo:spawn';  payload:{cargoId,cargoType,pose} }      // 生成货物（如舱门平台）
  | { type:'cargo:move';   payload:{cargoId,pose} }                // 货物位姿动画（进舱滑入等）
  | { type:'path:plan';    payload: PlannedPath }                  // 荧光路径（含避障绕行点）
  | { type:'obstacle:event'; payload:{agvId,pose,radius} }         // 障碍标注（6s 自动消退）
  | { type:'slot:mark';    payload:{slotId,state:'pending'|'clear'} } // 目标槽闪烁
  | { type:'door:set';     payload:{doorId:'forward'|'aft', state:'open'|'close'} };
```

AGV 增量指令 `AGVCommand{agvId,type,pose?,speed?,ts}`；场景对 moveTo 做位置逼近 + 朝向阻尼、近目标对准、到位判定后自动执行下一条，轮组随转向角偏转示意。

**上行 ControlCommand**（前端 → 算法/演示源）：`system:init|start|pause|reset`、`config:change`、`task:dispatch{TransportTask}`、`task:cancel`、`door:override`。

**传输帧（WS 对接时）**：下行帧 `{v:1, src:'algorithm', t:<event>, ...payload}`；上行 `{v:1, dst:'algorithm', cmd:<ControlCommand>}`。详细字段与示例见 `docs/算法接入协议.md`。

## 5. 核心业务流程与状态机

| 环节 | 触发（下行事件） | 3D 表现 | 状态同步 |
|---|---|---|---|
| 货物进舱 | `door:set`(open) → `cargo:spawn`(外平台) → `cargo:move`(滑入交接位) | 门扇外滑开启；ULD 过门洞滑入舱内交接位 | 门状态、cargo:waiting |
| AGV 取货 | `cargo:pickup` 预登记 + `agv:command moveTo(交接位)`→`pick` | AGV 驶至交接位，顶升台升起挂载货物 | AGV:toPickup→pickup；cargo:inTransit |
| 算法规划路径 | `path:plan`（含绕行点） | 荧光路径动态绘制 | — |
| 舱内自主运输 | `agv:command` 多段 moveTo | 位姿连续、轮组转向、状态环 | AGV:transport |
| 障碍自动避让 | `obstacle:event` + 绕行 `path:plan`/指令序列 | 障碍体高亮脉冲，路径绕行重规划 | 日志记录 |
| 抵达目标位 | `agv:command moveTo(槽位侧)` | 目标槽 `slot:mark` 闪烁 → 精确对位 | — |
| 货物排列放置 | `cargo:place` 预登记 + `agv:command place` | 顶升台下降，货物横向滑移入位写入槽位 | cargo:placed；slot:mark clear |
| 任务完成 | `task:state done` | 任务日志/面板更新，AGV 返回驻泊 | task done；AGV done→idle |

**两层状态机**（消除 v1 漂移）：

1. AGV 场景运行时状态（由指令/动作驱动，场景内部）：`idle | moving | aligning | pick | place | error`。
2. 任务/运输阶段（由算法源事件驱动，UI/看板展示）：`idle → toPickup → pickup → transport → placing → done → idle`（可含 error 分支）。前端只渲染，不做决策迁移。

## 6. 场景与演示几何规则

### 6.1 布局
机身剖开式：地板/侧壁/机头机尾隔板/顶部肋骨架；前后右舷舱门（门扇外滑动画 + 门框 + 外侧装卸平台）；槽位格线 + 槽位号文字；货位占用 = 实际放置的 ULD 实体（带三色类型区分与金属框线）；中央通道边线。全部尺寸读 config，`applyConfig` 后重建受影响几何并 dispose 旧对象。

### 6.2 货物模块
参数化 AKE/PMX/PAX（主体 + 轮廓线框 + 底部托盘示意；AKE 斜角以楔形示意）；槽位 Map 记录占用/空闲；状态（待装/在途/已入位）三色指示。初始装载与目标放置共用同一"装载规格函数"（代码单一来源，保证 store 镜像与场景一致）。

### 6.3 AGV 模块
车身 + 四转向轮（随转向角偏转示意）+ 顶升平台（升降缓动）+ 状态指示灯 + 载货挂点（货物随车/随平台抬升）。仅消费外部指令。

### 6.4 路径与障碍
路径 BufferGeometry 荧光折线 + 途经点；障碍由消息标注，前端只显示包围圈 + 光柱，生命期 6s。

### 6.5 货物-槽位几何适配（演示编排可行性过滤，非排布算法）
槽位列距 1.72m：AKE 需 1 列；PMX/PAX 需连续 2 空列。演示编排在选择目标槽时执行**列跨度适配**过滤；真实场景中"放哪"由算法方决定，前端仅在演示模式下给出候选列表（store 提供空闲/适配槽位给 UI 选择）。

### 6.6 演示编排物理约束（MockScheduler 生成消息的几何依据）
- 货物**经门洞滑入**舱内交接位（交接位 X=门心、Z=-1.0），不出现"载货 AGV 穿门/超高"。
- AGV 货载走廊限位：载货状态舱内行进时货物中心 |Z|≤0.5（货物半宽 0.767 + AGV 半宽 0.55，两侧留 ≥0.07 余量），避免与已放置货柜（内缘 |Z|≈1.433）干涉；空载转场沿 |Z|≤0.55 中线行进。
- 货载走廊的横向平移（-1.0 → ±0.5）只能在机头/机尾空场完成（空场无货位，全宽可用）。
- 到列后由 `place` 的"横向滑移入位"动画完成最终排列（落位位移 ≈1.7m），AGV 本体不入货位。
- 避障演示仅安排在机头/机尾空场或货位区起点前，保证"绕行通道"真实可行（空场全宽 ≥6m）。
- AGV-01 服务前段货位（列 0..2，前门装卸），AGV-02 服务后段（列 3..5，后门装卸）；单 AGV 配置时单台迁移服务全程。

### 6.7 演示流程（MockScheduler 编排一个货物的完整序列）
开前/后门 → 平台生成货物 → 滑入交接位 → AGV 从驻泊位驶往交接位（空场转向/避障演示）→ pick(顶升挂载) → 载货沿走廊至目标列（路径线 + 途经点渲染；随机插入障碍事件与绕行段）→ 横移入位 place(下降落位) → slot 目标态清除 → 门复位 → 任务完成。单货物模式 = 单任务 1 件；多货物同时装载模式 = 单任务含多件并按前后段/多 AGV 并行/串行编排。

## 7. 面板与操作能力（全部落地）

- **顶栏**：系统名/模式标识（演示/算法接入/连接状态）、运行按钮组（初始化 / 启动 / 暂停/继续 / 重置）、统计（在途/待命 AGV、任务完成数、运行模式、时钟）。

- **右栏-任务与状态看板**：任务控制（模式：单货物/多货物同时装载；货物类型与数量；目标槽"自动适配/手动选择"下拉；下发/取消）；运行 KPI（完成/进行中/待命）；任务列表（模式、货物、状态、进度）；AGV 实时卡（ID、阶段色环、任务、货载、驻泊/在位）；槽位占用缩略图（空闲/已装/指派中/目标选中色）。
- **底栏**：实时日志（事件流：开门/进舱/取货/路径/避障/入位/完成/错误）。
- **场景交互**：OrbitControls 旋转/缩放；无 IoT 拾取弹窗（已按确认移除）。

生命周期沿用现有：onMounted 建场景、ResizeObserver、onBeforeUnmount dispose。

## 10. 算法接入方式（外部算法方速览）

1. 前端不实现规划/避障/调度/排列/RL——只消费 §4 `AlgorithmEvent` 并转发 `ControlCommand`。
2. 接入：`AlgorithmAdapter` 面向 WS 连接（帧格式见 `docs/算法接入协议.md`）；前端 UI 提供模式切换与连接配置。
3. 前端需要的"位置反馈"通过场景探针/自身消息流获得；若算法方需要当前占用，可消费上行 `cargo:state`/`task:state` 或由本方维护。
4. MockScheduler 仅演示占位，不参与真实业务判定；切换接入模式后全部决策由算法方下发。
