# 第 3 页 · 一、场景：应用场景

**页面要点**

- **作业场景**：航空公司 / 货运站的**飞机货舱（散货舱 / 下舱）装载作业**——货物经舱门进入货舱，由 AGV 在**舱内狭窄走廊**完成取货、运输、避障、入位排列。
- **典型对象**：标准航空集装箱与托盘（AKE/LD-3、PMX、PAX），货舱布局为**中央通道 + 两侧货位排**（本项目默认：舱长 24 m、地板宽 6.8 m、通道宽 2.3 m、两侧各 6 列货位、前后两个右舷舱门）。
- **作业流程**：开门 → 货物经门洞滑入舱内交接位 → AGV 空驶至交接位取货 → 算法规划路径 → 舱内自主运输 → 遇障绕行 → 抵达目标列 → 横向滑移入位 → 任务完成复位。
- **可推广场景**：航空货运站、冷链/医药货舱、集装箱内装卸、任何「狭窄空间 + 无卫星定位 + 人机混行」的室内运输场景。

**讲稿提示**：把场景讲成「**空间极窄、视线极差、定位极难、安全要求极高**」四个特征，后面所有技术要求都由这四点推导出来。

**建议配图**：货舱剖面示意图（本项目三维场景俯视图 + 尺寸标注）。

# 第 4 页 · 场景：为什么必须是「数字孪生 + AI」而不是单点算法

**页面要点**

- 真实飞机货舱**不可用于反复试错**：占用机时成本极高、安全规程限制、无法为了训练算法反复开关舱门。
- 因此系统必须是**三层结构**：
  - **物理/半实物层**：真实 AGV、相机、舱体或缩比舱段；
  - **算法层**：视觉识别（感知）、强化学习路径规划（决策）、路径寻迹控制（执行）；
  - **数字孪生层**：统一可视化底座 + 统一契约 + **几何与安全校验的裁判** + 数据回放与指标采集。
- 孪生的价值不在"好看"，而在**把不可反复试错的现场，变成可反复试错的沙盘**，并且它是**唯一同时掌握全局真值的一方**（谁偏了多少、谁超时了、哪条路径真的走通了）。

**讲稿提示**：这一页是「场景 → 痛点」的桥梁，用一句话收尾：**"没有孪生，三家的算法没法放在一起验收。"**

**建议配图**：物理层 / 算法层 / 孪生层三层关系图。

# 第 5 页 · 二、痛点：作业层面的痛点

**页面要点**（建议每一条都配一个「人工现状 → 后果」的短句）

1. **装载效率低、舱位利用率靠经验**：配载与装箱顺序依赖人工经验，装机单与实际装载常有偏差，返工多。
2. **舱内视线盲区大**：货舱低矮狭窄、货物遮挡严重，操作员看不到 AGV 与货物的实时位置，只能靠喊话/手势。
3. **人机混行安全风险高**：AGV、装卸人员、登机平台在同一狭小空间作业，碰撞与夹伤风险靠人的注意力兜底。
4. **信息不透明、进度不可见**：装到哪了、还剩几个位、哪个货柜放错列，现场与后台都不掌握。
5. **多机协同调度难**：通道只有一条，两台 AGV 相向或同时进出通道极易死锁，而现有调度多为规则/人工指挥。
6. **训练与验证成本高**：新算法、新底盘、新流程没有安全可控的试验场，只能"上真机试"。

**讲稿提示**：把 6 条归纳成两类——**"看不见"（感知/信息）与"不敢试"（决策/验证）**，正好对应视觉识别与强化学习两个方向。

# 第 6 页 · 痛点：现有技术手段为什么不够

**页面要点**

| 现有手段 | 局限 |
|---|---|
| 人工/叉车/牵引车 | 舱内空间不允许回转，效率与安全都靠人 |
| 传统 AGV（磁条/二维码） | 舱内地面不允许大量铺设与维护标记；改布局即返工 |
| 激光 SLAM | 舱内金属壁面**镜面反射 + 重复纹理**，特征退化；空间窄，几何约束少 |
| GNSS/RTK | 舱内/机腹**无卫星信号**，不可用 |
| 单点路径规划（A*/Dijkstra） | 静态地图可行，但动态障碍、多机冲突、死锁恢复能力弱 |
| 纯规则调度 | 布局一变就要重写规则，无法适应新货型/新槽位组合 |

**讲稿提示**：这一页的目的是**证明"必须上视觉感知 + 学习型决策"**，而不是为了用 AI 而用 AI。

# 第 7 页 · 三、总体架构：感知—决策—控制—孪生 四层

**页面要点**

```
┌── 感知层 ──┐   ┌── 决策层 ──┐   ┌── 控制层 ──┐
│ 视觉识别    │   │ 强化学习    │   │ 路径寻迹    │
│ 检测/定位/  │→  │ 路径规划/   │→  │ 横向误差    │
│ 装载复核    │   │ 多机调度    │   │ 速度控制    │
└─────┬──────┘   └─────┬──────┘   └─────┬──────┘
      │ 感知事件        │ 路径与决策      │ 跟踪遥测
      └────────┬────────┴────────┬───────┘
               ▼                 ▼
        ┌────────────────────────────────┐
        │  统一消息契约（WebSocket / JSON）│
        │  统一坐标系（机体右手系，单位 m） │
        │  统一时钟（单调 ts + 插值缓冲）  │
        └───────────────┬────────────────┘
                        ▼
        ┌────────────────────────────────┐
        │  数字孪生层（本项目已交付）      │
        │  三维渲染 · 状态看板 · 几何校验  │
        │  安全看门狗 · 录制回放 · 指标采集│
        └────────────────────────────────┘
```

- **单向数据流**：算法只"下发事件"，孪生只"消费渲染 + 转发控制"，**孪生不实现任何规划/避障/调度/排列算法**（避免双源真相）。
- **可替换性**：同一契约下，演示编排源 ↔ 真实算法源可热切换，这是三方并行开发的前提。

**讲稿提示**：强调「**契约即接口**」——组内三方不用互相等代码，各自对着契约开发即可。

# 第 8 页 · 技术要求（1）功能与接口要求

**页面要点**

| 编号 | 要求 | 判据 |
|---|---|---|
| R1 | **统一坐标系**：机头为原点，+X 机尾向、+Y 上、+Z 左舷；单位米、角度弧度 | 与 three.js y-up 右手系同构，无轴重映射 |
| R2 | **统一消息契约**：下行 `AlgorithmEvent`（场景指令 + 任务/AGV/货物状态 + 日志），上行 `ControlCommand`（初始化/启停/重置/配置变更/任务下发取消/舱门手动） | 契约以代码 (`src/types/cargo.ts`) 为唯一依据，文档同步 |
| R3 | **可接入性**：WebSocket 为主（HTTP/SSE 预留），断线自动重连（当前指数退避，上限 8 s） | 未连接时控制指令给出明确告警，不静默丢弃 |
| R4 | **可配置性**：货舱/舱门/AGV/ULD 三类货柜/槽位的全部尺寸参数可改，改后整场景重建 | 参数单点定义，UI 修改即重建并 dispose 旧对象 |
| R5 | **几何可行性过滤**：槽位节距 1.72 m 下，AKE 占 1 列、PMX/PAX 需连续 2 空列；载货走廊货物中心偏差限位 | 演示模式下前端过滤，真实模式由算法决策（见第 27 页 G7） |
| R6 | **状态镜像**：任务/AGV 阶段/货物状态/门状态/日志在孪生侧完整镜像 | 看板与场景永远同源，不出现"幽灵货物" |

**讲稿提示**：R1–R3 是三方联调的"交通规则"，R4–R6 是孪生侧已兑现的部分。

# 第 9 页 · 技术要求（2）性能、工程与安全要求

**页面要点**

- **实时性**：控制环与可视化必须**分通道**——控制环 ≥ 50 Hz，可视化 10–20 Hz；孪生侧需 100 ms 级插值缓冲以抗抖动与乱序。
- **精度**：舱内定位（无 GNSS）≤ 20 mm；到位 ≤ ±10 mm；孪生显示误差 ≤ 10 mm。
- **稳定性**：连续 24 h 运行无内存增长（几何 dispose 全覆盖）、断链 3 s 内恢复、消息丢帧率 ≤ 0.1%。
- **可追溯**：全量事件可落盘、可回放、可导出指标（评审要求"能复现"）。
- **安全**：任何人机混行场景必须有**独立于学习型算法**的安全层（限速、软/硬急停、可达性约束），学习型算法只出"候选动作"而不能直接驱动底盘。
- **可扩展**：新增货型、槽位、AGV 数量不应改动契约主干；新增感知/决策/控制事件采用"未知类型忽略"策略向后兼容。

**讲稿提示**：这一页是给评审的"工程严肃性"证明：**安全不交给神经网络**。

> 结论一句话：**"看得见"的部分（可视化、接口）已经比较成熟；"看得准、想得对、走得稳"三件事都不成熟，且不成熟的原因不是算法写不出来，而是数据、仿真环境与安全层缺失。**

**讲稿提示**：主动说出"哪些不成熟"，比被评审问出来可信得多。等级口径说明见下一页。

# 第 14 页 · 成熟度判据：为什么这几项"不成熟"

**页面要点**（每条都是"机理级"原因，不是"还没做完"）

1. **无卫星定位 + 金属舱体**：舱内 GNSS 不可用；金属壁面镜面反射、重复纹理使纯视觉/激光特征退化，定位退化无冗余 → 必须**多源融合 + 标定基准**。
2. **空间极窄、容错极小**：通道半宽 1.15 m，货柜内缘 |Z|≈1.43 m，横向误差一旦超过几十毫米就会干涉 → 对寻迹精度要求高于普通仓储 AGV。
3. **学习型决策缺乏安全性证明**：强化学习只能给出**概率最优**，无法保证"永不碰撞"；真实场景必须由**规则/可达性约束层**兜底。
4. **sim2real 差距**：接触摩擦、顶升负载偏心、地面不平、通信与执行时延，仿真里都难以精确复现。
5. **数据稀缺**：航空货舱内的实拍标注数据几乎无公开数据集，冷启动困难。
6. **孪生当前不是仿真器**：本项目孪生是"渲染 + 契约执行"，**没有物理引擎/接触模型**，因此不能直接当 RL 训练环境使用（见第 27 页 G10）。

**讲稿提示**：第 6 点是很容易被问到的"硬伤"，主动说 + 给方案（对接外部物理仿真，孪生做可视化与验收）。

# 第 15 页 · 七、成熟度量化指标（总览：怎么定义"成熟"）

**页面要点**

- 用**五类指标**定义"从原型到可用"，每类都有硬门槛：
  1. **精度类**：定位误差、到位误差、跟踪误差、孪生一致性；
  2. **效率类**：节拍、makespan、路径长度、舱位利用率；
  3. **可靠性类**：成功率、碰撞次数、死锁恢复、长稳、丢帧率；
  4. **实时性类**：推理时延、控制时延、端到端"消息→像素"延迟；
  5. **泛化与鲁棒类**：货型/槽位/AGV 数量组合、光照与遮挡退化、载重变化。
- **判定规则（建议）**：
  - 每条指标给出 **目标值 / 门槛值 / 当前值** 三列，缺"当前值"即视为未验证；
  - **"成熟"= 全部硬门槛达标 + 连续 ≥100 次作业无致命故障 + 指标可复现（有回放与原始数据）**；
  - **"碰撞次数"与"人员安全相关漏检"为零容忍硬门槛**，不参与加权。

**讲稿提示**：这一页回答"什么叫成熟"，后面四页是逐项展开。**强调"当前值要由我们三方一起补测"**，这是下一步的主要工作量。

# 第 21 页 · 八、三方算法与数字孪生怎么整合（总设计）

**页面要点**

- **三条铁律**：
  1. **统一坐标系**（机体右手系 + 米/弧度）——所有位姿只在这一套坐标里传递；
  2. **统一契约**（`AlgorithmEvent` 下行 / `ControlCommand` 上行）——未知事件类型一律忽略并告警，保证向后兼容；
  3. **统一时钟**——所有消息带单调递增 `ts`，孪生侧做 100 ms 插值缓冲，抗抖动与乱序。
- **两条通道分离**（**[建议]** 本次提出）：
  - **可视化通道**：状态/事件类消息，10–20 Hz，JSON/WS，走孪生；
  - **控制通道**：高频指令与遥测（寻迹环 50–200 Hz），走二进制/DDS/共享内存，**不经过浏览器**，孪生只订阅其中抽取后的低频遥测。
- **孪生的三重角色**：**显示者**（可视化）、**裁判者**（几何/安全校验与指标采集）、**记录者**（录制回放，支撑复现与复盘）。
- **整合顺序（建议）**：契约对拍（已完成）→ 离线回放接入 → 数字孪生在环（DiL）闭环 → 半实物（HIL）→ 现场小规模。

**讲稿提示**：把"两条通道分离"讲成**工程必需**而不是优化项：50 Hz 控制环绝不能和三维渲染抢浏览器主线程。

# 第 22 页 · 整合（1）视觉识别 → 数字孪生（感知层）

**页面要点**

- **视觉给孪生什么**：
  1. **检测框与类别**（AGV / ULD / 障碍 / 人员）→ 孪生侧做**检测框叠加渲染**（可解释性 + 现场感），
  2. **ULD 类型与到位复核** → 孪生侧做"视觉 vs 孪生真值"的双向校验，差异超阈值即告警，
  3. **AGV 视觉定位位姿**（无 GNSS 的舱内定位）→ 作为孪生位姿的**修正源**与误差曲线来源，
  4. **障碍/人员进入** → 直接产生 `obstacle:event`，触发规则层减速/停车与路径重规划。
- **孪生给视觉什么**：孪生提供**虚拟相机位姿与渲染图**，可做"虚拟数据增强 / 预标注"，缓解舱内实拍数据稀缺（这是孪生反哺感知的关键价值）。
- **新增契约（**[建议]**）**：`perception:detect`、`agv:localization`、`cargo:verify`（字段定义见附录 A）。
- **联调里程碑**：离线视频 → 孪生叠加（DiL）→ 相机现场接入。

**讲稿提示**：一句话概括——**"视觉让孪生有眼睛，孪生让视觉有数据。"**

# 第 23 页 · 整合（2）强化学习路径规划 → 数字孪生（决策层）

**页面要点**

- **RL 给孪生什么**：
  1. `path:plan`（在已有契约上扩展 `planner: 'rl' | 'astar' | 'hybrid'`、`planningMs`、`replanReason`）→ 孪生里**按代价/价值给路径着色**，区分初规划与重规划绕行，
  2. `rl:decision`（每步动作、即时回报、探索标志、推理时延）→ 孪生显示**动作箭头 + 决策解释层**，
  3. `rl:episode`（训练/评测回合：步数、总回报、成功与否、makespan、碰撞数）→ 孪生看板显示**训练/评测曲线**。
- **孪生给 RL 什么**：
  1. **几何可行性校验**（越界、干涉、超高、载货走廊限位）→ 不合法的规划立即告警，
  2. **统一评测口径**：同一批场景回放，对 RL 与 A*/规则调度做**同条件对比**（路径长度、makespan、碰撞），
  3. **[规划中]** 若要把孪生当训练环境，必须补运动学 + 接触模型，或对接外部物理仿真（见第 27 页 G10）。
- **安全边界**：RL 输出作为**候选**，经安全层（可达性/限速/优先级）筛选后才下发 `agv:command`。

**讲稿提示**：强调**"可对比、可复现"**——RL 的收益必须能在孪生里用同一套指标证明，否则无法验收。

# 第 24 页 · 整合（3）路径寻迹控制 → 数字孪生（控制层）

**页面要点**

- **寻迹给孪生什么**：`agv:trace` 遥测——当前目标航点索引、**横向误差 crossTrackError**、**航向误差 headingError**、速度、曲率、控制器是否饱和。
- **孪生在寻迹里的三个用途**：
  1. **可视化**：AGV 实际轨迹按误差着色（绿 ≤30 mm / 黄 ≤50 mm / 红 >50 mm）+ 实时误差曲线；
  2. **量化**：孪生是唯一掌握"指令路径 vs 实际轨迹"两侧数据的一方 → 直接算出跟踪误差 RMS/峰值、到位精度、超调量；
  3. **整定**：参数整定前后同一条路径回放对比，形成"参数-指标"档案，避免"感觉变好了"。
- **新增契约（**[建议]**）**：`agv:trace`（低频抽样 10–20 Hz 进孪生；原始 50 Hz+ 留在控制通道）。
- **联调顺序**：先离线轨迹回放 → 再实时 DiL（孪生发路径、真机/仿真车跟踪、遥测回孪生）。

**讲稿提示**：一句话——**"控制的好坏，孪生替你量出来。"**

# 第 25 页 · 整合（4）数字孪生反向赋能：校验、看门狗、回放

**页面要点**

- **几何校验器 [建议]**：对所有下行路径与位姿做实时校验——越界（舱壁/槽位区）、与已放货物干涉、超高（舱门净高 2.0 m）、载货走廊限位（|Z| ≤ 0.5）；违规即上行 `safety:violation` 并高亮显示。
- **安全看门狗 [建议]**：心跳超时（某算法源 >1 s 无消息）自动降级为"安全停机/人工接管"，并在孪生上明确标识"当前数据不可信"。
- **录制与回放 [建议]**：全量消息落盘为 JSONL（含时间戳与源标识），支持倍速回放、断点重演、指标重算——**这就是"可复现"的载体**，也是评审与验收的证据链。
- **指标自动采集 [建议]**：把第 16–20 页的指标做成自动跑批（给定场景集 → 输出 CSV/图表），成为小组的"数字验收报告"。
- **价值升华**：做到这四点，孪生就从"可视化大屏"升级为**系统级验收与安全平台**，这也是本项目区别于普通三维演示的核心竞争力。

# 附录 A · 契约 v1.1 扩展建议（可直接发给三位成员）

> 原则：**向后兼容**——`v` 保持 1，未知 `t` 一律忽略并告警；所有新增事件都带 `ts`（单调递增，毫秒）。

```ts
// ===== 感知层（视觉识别）=====
| { type: 'perception:detect'; payload: {
    frameId: number; ts: number;
    source: 'rgb' | 'depth' | 'fused';
    detections: Array<{
      class: 'AGV' | 'ULD' | 'obstacle' | 'human' | 'door';
      confidence: number;                   // 0..1
      bbox: [number, number, number, number]; // 像素 [x, y, w, h]
      pose?: Pose3;                         // 标定后可反投影到机体坐标
      cargoType?: CargoType;                // ULD 细分类型
      trackId?: string;                     // 跨帧跟踪 id
    }>;
  } }

| { type: 'agv:localization'; payload: {
    agvId: string; pose: Pose3;
    source: 'vision' | 'fiducial' | 'fusion';
    confidence: number;                     // 0..1
    residual: number;                       // 与预测位姿的偏差(m)，孪生用于误差曲线
    ts: number;
  } }

| { type: 'cargo:verify'; payload: {
    cargoId: string; slotId: string;
    ok: boolean; pose?: Pose3;
    deviation?: number;                     // 到位偏差(m)
    ts: number;
  } }

// ===== 决策层（强化学习路径规划）=====
| { type: 'path:plan'; payload: PlannedPath & {
    planner?: 'rl' | 'astar' | 'hybrid';
    episodeId?: string;
    cost?: number;
    planningMs?: number;
    replanReason?: 'obstacle' | 'deadlock' | 'none';
  } }                                        // 在原契约上做可选字段扩展

| { type: 'rl:decision'; payload: {
    episodeId: string; step: number; agvId: string;
    action: { v: number; omega: number } | { target: Pose3 };
    reward: number; value?: number;
    explore: boolean; inferenceMs: number;
    modelVersion: string;
  } }

| { type: 'rl:episode'; payload: {
    episodeId: string; phase: 'train' | 'eval';
    status: 'start' | 'end';
    steps: number; totalReward: number;
    success: boolean; makespan?: number; collisions?: number;
    epsilon?: number; modelVersion: string;
  } }

// ===== 控制层（路径寻迹）=====
| { type: 'agv:trace'; payload: {          // 孪生订阅抽样后的 10~20 Hz
    agvId: string; ts: number;
    waypointIndex: number;
    crossTrackError: number;                // 横向误差(m)
    headingError: number;                   // 航向误差(rad)
    speed: number;                          // m/s
    curvature?: number;                     // 1/m
    controllerSat?: boolean;                // 控制量是否饱和
  } }

// ===== 孪生 → 算法（上行告警，新增 ControlCommand）=====
| { type: 'safety:violation'; payload: {
    kind: 'outOfBound' | 'interference' | 'overHeight' | 'collision' | 'stale';
    agvId?: string; cargoId?: string;
    pose: Pose3; detail: string; ts: number;
  } }
```

# 附：三分钟精简口播稿（若汇报时间被压缩）

> 我们的场景是**飞机货舱内的 AGV 装载**：空间极窄、视线极差、没有卫星定位、人机混行，四个特征决定了它既"看不见"又"不敢试"。
> 我们的做法是把**视觉识别、强化学习路径规划、路径寻迹控制**三条算法链接到同一个**数字孪生底座**上，靠**统一坐标系、统一消息契约、统一时钟**耦合，任何一方都能独立迭代、可替换、可回放。
> 数字孪生侧我已经交付了可演示的完整原型：参数化三维货舱、双舱门、三类标准货柜、两台 AGV 全流程演示、以及真实算法的 WebSocket 接入框架，构建质量门零错误，线上永久地址可以直接用手机打开。
> 成熟度上要如实说：**可视化和接口比较成熟（TRL 5–6）**；**视觉识别、强化学习规划、寻迹控制都还在原理样机阶段（TRL 3–4）**，端到端集成只有契约级验证。不成熟的机理是舱内金属反光导致定位退化、学习型决策没有安全性证明、sim2real 存在差距，加上舱内实拍数据稀缺。
> 所以我把"什么叫成熟"写成了可测的指标表：精度、效率、可靠性、实时性、泛化五类，其中**碰撞为零和人员零漏检是硬门槛**，其余给出建议阈值，等三方一起补测"当前值"。
> 需要专家指导三件事：**指标阈值是否需要按航空规程加严、联调顺序如何取舍、是否引入外部物理仿真作为训练环境**。
