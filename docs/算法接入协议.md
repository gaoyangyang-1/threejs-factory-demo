# 算法接入协议（Algorithm Adapter Protocol）v1.1

> 面向真实路径规划 / 避障 / 多 AGV 调度 / 货物排列 / 强化学习算法方。前端**不实现**任何算法逻辑，
> 仅消费下行 `AlgorithmEvent` 渲染三维场景与同步状态，并把用户操作作为上行 `ControlCommand` 转发。
> 坐标系/单位与消息结构详见 `docs/方案.md` §1/§4 与 `src/types/cargo.ts`（**代码为唯一依据**）。
>
> **v1.1 变更（相对 v1）**：
> - 只有**一个前舱门**，`DoorId` 仅剩 `'forward'`（不再有 `aft`）；
> - AGV **在舱外前舱门平台待命**，任务下发后货物直接装到车上，由 AGV 载货穿门进舱（不再有舱内交接位滑入）；
> - 货舱地板**全宽度可放货**：货位号新增中央排 `SLOT-C-xx`，共 L/R/C 三排；不再有 AGV 专用通道与载货走廊限位；
> - 入位方式为"AGV 停在目标列前方 1.8 m，货物沿 +X 推入货位"。

## 1. 坐标系与单位（对接前必读）

- 机体右手系：**货舱前隔板中心为原点 `O(0,0,0)`**；机头锥段在 `X<0`，`+X` 逆航向指向机尾；`+Y` 竖直向上（地板面 `Y=0`）；`+Z` 指向飞行方向左侧（左舷）。
- 全部长度为**米**；角度为**弧度**。
- 位姿结构 `Pose3 = { x, y, z, yaw }`，`yaw` 绕 `+Y`：`0`→+X（朝机尾），`+π/2`→-Z（右舷），`-π/2`→+Z（左舷，进舱方向）。
- 货位 id：`SLOT-L-00 … SLOT-R-{n}`、`SLOT-C-00 … SLOT-C-{n}`（L=左舷 +Z、R=右舷 -Z、C=中央 Z=0，00 起从机头向机尾）。
- AGV id：`AGV-01…`；舱门：`forward`（唯一）；货物 id 由算法方生成（唯一即可）。

## 2. 传输与帧格式

- WebSocket（前端支持；HTTP 轮询/SSE 预留）。默认地址示例：`ws://127.0.0.1:9001/algorithm`（前端面板可配置）。
- 每帧一个 JSON 文本消息。

**下行（算法 → 前端）**

```json
{ "v": 1, "src": "algorithm", "t": "agv:command", "payload": { "agvId": "AGV-01", "type": "moveTo", "pose": { "x": 5.3, "y": 0, "z": -0.5, "yaw": 0 }, "speed": 1.2, "ts": 100 } }
```

- `t` 与 `payload` 结构 = `AlgorithmEvent`（见下表）。场景只消费其中 `SceneCommand` 子集；任务/AGV/货物状态事件驱动看板。

**上行（前端 → 算法）**

```json
{ "v": 1, "dst": "algorithm", "cmd": { "type": "task:dispatch", "task": { "id": "T-001", "mode": "single", "items": [ { "cargoType": "AKE", "slotId": "SLOT-L-02" } ] } } }
```

`cmd` 结构 = `ControlCommand`：`system:init|start|pause|reset`、`config:change`、`task:dispatch`、`task:cancel`、`door:override`。
> 算法接入模式下前端不代选槽位（`slotId` 可缺省，由算法决策后经 `cargo:place`/`cargo:spawn` 下发）。

## 3. 下行事件速查

| t | payload | 消费方 |
|---|---|---|
| `scene:reset` | `{ config }` | 场景全量重建（算法自持布局） |
| `agv:command` | `AGVCommand`：`moveTo/turnTo/stop/pick/place` + `pose/speed/ts` | 场景增量执行 |
| `cargo:pickup` | `{ agvId, cargoId }` | 场景登记取货（把舱外货物挂到车上） |
| `cargo:place` | `{ agvId, cargoId, slotId }` | 场景登记放货（推入货位） |
| `cargo:spawn` | `{ cargoId, cargoType, pose }` | 场景生成货物（可给 AGV 当前位姿，即"货直接上车"） |
| `cargo:move` | `{ cargoId, pose }` | 货物位姿动画 |
| `path:plan` | `{ agvId, waypoints: Pose3[] }` | 荧光路径（含绕行点） |
| `obstacle:event` | `{ agvId, pose, radius }` | 障碍圈高亮（7s 消退） |
| `slot:mark` | `{ slotId, state: 'pending'|'clear' }` | 目标货位闪烁 |
| `door:set` | `{ doorId: 'forward', state: 'open'|'close' }` | 前舱门动画 |
| `task:state` | `{ taskId, status, progress, message }` | 任务看板 |
| `agv:state` | `{ agvId, phase, taskId?, cargoId?, cargoType? }` | AGV 看板 |
| `cargo:state` | `{ cargoId, status, slotId?, cargoType? }` | 货物看板/货位占用 |
| `log` | `{ level, message }` | 日志流 |

> `agv:state.phase` ∈ `idle|toPickup|pickup|transport|placing|done|error`；`cargo:state.status` ∈ `waiting|inTransit|placed`。

## 4. 一个完整业务流程（算法方应下发的序列示例）

1. `door:set {doorId:'forward', state:'open'}`
2. `cargo:spawn {cargoId, cargoType:'AKE', pose:<AGV 当前位姿>}` → `cargo:pickup {agvId,cargoId}` → `agv:command {type:'pick'}`（货物直接挂到舱外待命的 AGV 上）
3. 载货穿门进舱：`path:plan {agvId, waypoints:[…]}` + 多段 `agv:command moveTo`（舱外平台 → 舱内入口 → 机头空场横向转场 → 目标列前方 1.8 m）
4. 如遇障：`obstacle:event` + 含绕行点的重规划路径/多段 `moveTo`
5. 推入入位：`cargo:place {agvId,cargoId,slotId}` → `agv:command {type:'place'}`（货物沿 +X 推入货位）
6. 退回待命：多段 `moveTo`（出舱回平台）；状态同步：`cargo:state {cargoId,status:'placed',slotId}`；`agv:state {phase:'done'→'idle'}`；`task:state done`
7. `door:set {doorId:'forward', state:'close'}`

**几何约定（保证前端渲染与物理可行）**：只有一扇前舱门（净高 2.5 m，载货 AGV 总高约 2.3 m 可通过）；货位为 L/R/C 三排，左右两排中心 |Z|=2.3、中央排 Z=0，货位格之间净空 ≥0.76 m；货位**由机尾向机头填充**，使 AGV 从机头空场进入时沿途货位为空；入位时 AGV 停在目标列前方 1.8 m，货物推入货位（AGV 不进入货位）；宽体货（PMX/PAX）需连续 2 个空列。

## 5. 演示编排源（MockScheduler）说明

前端内置"演示编排源"仅为**无算法后端时的展示占位**：它按上述同一契约、依据前端布局几何生成完整演示剧本（含避障绕行），不包含任何算法实现。切换"算法接入"后请忽略演示源输出。

## 6. 调试建议

- 前端日志会提示"忽略无法解析的帧"，可据此对齐字段名。
- 所有消息 id/ts 单调递增便于去重；场景指令按 `ts` 忽略重发。
- 场景位姿查询（供算法方做完成判定）由场景探针提供，本协议默认假设算法方通过自身仿真步进推进，前端按收到的位姿/指令渲染。
